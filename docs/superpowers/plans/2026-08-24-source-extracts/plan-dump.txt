Heading 1 | 1. Executive Summary
? | This project delivers a commercial home router that behaves as a security appliance for non-technical households. Industry research shows the core market gap clearly: roughly 8 in 10 users never change their router's default admin password and never update its firmware — yet nearly 8 in 10 know how to access router settings. The barrier is not ability but motivation and clarity: 73% of users do not know why they would need to change anything. No mainstream router product has solved this; competitors simplified setup but not security itself.
? | Our product answers that gap with three pillars: (1) secure by default — unique per-unit credentials, forced password change, automatic signed firmware updates; (2) plain-language security — a single dashboard status a non-expert understands, with one-tap fixes; (3) network-level parental controls that children cannot bypass by deleting an app, which is the primary weakness of today's app-based controls.
? | The product is built on OpenWrt (custom firmware image), with a purpose-built on-device daemon and API, cross-platform mobile/web apps, RAUC A/B signed updates, and — in a post-launch release — outbound-only WireGuard remote access. The plan below phases delivery into an MVP launch followed by two feature releases, with hardware and security assurance running as parallel, launch-gating workstreams.
Heading 1 | 2. Project Goal & Objectives
? | Goal: launch a sellable router device that makes a home network measurably safer for a non-technical family, manageable in under 30 seconds per task, with zero networking knowledge required.
Heading 2 | Objectives
List Paragraph | O1 — Secure by default: A customer who does nothing beyond guided setup ends with changed credentials, encrypted Wi-Fi, and automatic updates enabled.
List Paragraph | O2 — Legible security: The dashboard communicates network safety in plain language (green/yellow/red + one-line reason) with one-tap remediation.
List Paragraph | O3 — Unbypassable family controls: Parental profiles (content categories, time limits, bedtime, instant pause) enforced at the network level.
List Paragraph | O4 — Resilience: Full local management and offline-capable MFA (TOTP/backup codes) with the internet down; the user is never locked out of their own hardware.
List Paragraph | O5 — Commercial readiness: Certified hardware, externally audited software, factory provisioning of unique credentials, and a staged OTA pipeline able to patch the entire fleet within days.
List Paragraph | O6 — Future-proofing: Architecture leaves the door open for ISP centralized management (TR-069/TR-369 class) without rework — explicitly out of scope to build now.
Heading 1 | 3. Scope
Heading 2 | In scope — MVP (launch release)
List Paragraph | Custom OpenWrt firmware, on-device daemon and unified local API; LuCI excluded from the consumer product.
List Paragraph | Local-first guided onboarding: unique per-unit default credentials, forced credential change, router naming, MFA enrollment (SMS/push default; TOTP + backup codes verified locally for offline use).
List Paragraph | Security dashboard with plain-language status and one-tap fixes; device list with friendly names, pause/block, new-device alerts.
List Paragraph | Website & content-category blocking with a friendly block page (no self-serve unblock; HTTPS handling designed explicitly); parental profiles with content filters, time limits, bedtime schedules, instant pause.
List Paragraph | Offline resilience: full LAN management without internet; physical recovery mechanism; automatic signed A/B firmware updates (RAUC) with staged/canary rollout from a cloud OTA service.
List Paragraph | Optional cloud account (local config always preserved when linking); in-app self-help troubleshooting.
List Paragraph | Hardware workstream: SoC selection, factory credential provisioning, recovery-button spec, regulatory certification, pilot production.
List Paragraph | Security assurance: external penetration test (launch-blocking), child-data privacy compliance, vulnerability disclosure policy and patch SLA.
Heading 2 | In scope — post-launch releases
List Paragraph | v1.1: Remote access (outbound-only WireGuard via relay; management-only scope by default), remote visibility + control, session alerts/revocation, ad blocking, guest network, multi-router accounts, weekly usage reports, per-app blocking (scope set by feasibility spike), support remote diagnostics.
List Paragraph | v1.2: Advanced Mode: technical device details, VLAN/IoT isolation, custom block lists, full-LAN remote access, port forwarding/DNS/static IP, manual update approval, custom ad-block lists, detailed security logs.
Heading 2 | Explicitly out of scope
List Paragraph | ISP centralized management (TR-069/TR-369, ACS integration, ISP dashboards) — future project; architecture keeps compatibility but nothing is built.
List Paragraph | Traffic-protection consumer VPN (routing household traffic through commercial VPN exit servers) — the product's VPN is a remote-access channel, not a privacy tunnel.
List Paragraph | Mesh/multi-node Wi-Fi systems in v1 hardware.

Phase | Sprints | Focus & exit criteria
