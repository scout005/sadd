Product Backlog & User Stories

Sadd Home Router — Simple by Default, Powerful Underneath

Prepared by: Product Owner / Scrum Master  ·  Version: v0.2 — Merge & Expansion Pass

Revision note (v0.2): This document merges Sadd's original product brief (home-router-user-needs-analysis.md Part 6) with gated-in requirements from a newly-completed Firewalla/"Sentinel" competitive research pass (01-Competitive-Analysis-Firewalla.html, 02-Product-Backlog-User-Stories.html). Sadd's brand, simple-first positioning, and Simple/Advanced Mode split are unchanged and are not up for revision here — this pass adds formal Epic → User Story → Acceptance Criteria structure (which Sadd did not previously have in document form) and pulls in applicable Sentinel material, tier-gated so nothing bypasses Sadd's "simple by default" promise. The pre-merge repository state is tagged v1 in git.

Every story below carries two tags: a tier (Simple Advanced Business — which layer of Sadd's interface it lives in) and a provenance (Sadd already implied/stated in Sadd's existing docs, now formalized · Sentinel pulled in from the new reference backlog, tier-gated · New synthesized during this merge, not sourced from either existing doc).

1. Product Vision

Simple by default, powerful underneath. A router that gives a non-technical household the protection level of a prosumer setup — without ever requiring them to touch a settings menu to get it — while never walling off the advanced user who wants full control.

Sadd competes by matching prosumer-grade security tools (Firewalla-class DPI, IDS/IPS, VLAN segmentation, VPN) feature-for-feature, delivered through the simplicity of eero-class onboarding, and differentiates on three things neither camp fully offers today: a true progressive-disclosure interface (Simple Mode default, Advanced Mode opt-in, never a prerequisite), free-for-life core security with no subscription required for baseline protection, and a mobile app that gives full remote access — VPN, cameras, parental controls — from anywhere, not just local Wi-Fi.

Sadd is built on OpenWrt (see Epic 18), giving it a real, evidence-based "built on a router-native embedded OS" claim rather than a generic open-source marketing line — mirroring the architecture rationale confirmed in the competitive analysis (Firewalla itself runs on Ubuntu, not a router-native OS).

5. Release Roadmap

Roadmap phases follow Sadd's own MVP/V2 split from home-router-user-needs-analysis.md §6.3/§6.4, now expressed against the full epic list above.

MVP / Release 1.0 — "Simple, Safe, and Trusted"

All P0 stories from Epics 1–11 (onboarding through privacy) — Sadd's core promise: dead-simple setup, real prosumer-grade protection on by default, plain-English transparency, no subscription for core security. Plus the P0 platform-foundation work from Epic 18 (version lock, GPL boundary, OTA, package manifest, the on-router agent daemon) and the Epic 15 compliance gate if Sadd ships its own hardware.

Release 1.1 — "Power & Reliability"

Remaining P1 stories: Advanced Mode depth across Epics 2/3/6/9/10, Epic 16's video walkthroughs and accessibility audit, Epic 18's LuCI-based Advanced Mode web UI, Epic 14's incident-response playbook and upstream-tracking SLA.

Release 2.0 — "Scale & Extensibility"

Epic 13 (Fleet/Business tier) in full, Epic 12's remaining P2 developer stories, Epic 6's site-to-site VPN and AmneziaWG, Epic 9's load balancing.

6. Definition of Ready (DoR)

A story is ready for sprint planning when it has: a clear persona and benefit statement; acceptance criteria written in checklist or Given/When/Then form; a tier tag and a provenance tag; no open UX/design dependencies; estimated by the team, not just the PO.

7. Definition of Done (DoD)

A story is done when: acceptance criteria pass in QA on all supported hardware tiers; a Simple-tier story reads in plain language with zero exposed jargon (ties to Epic 4's transparency principle — this is Sadd's non-negotiable bar, not a nice-to-have); Advanced/Business-tier stories are reachable only through their designated escape hatch, never surfaced by default; telemetry/logging respects Epic 11's local-first defaults; documentation published; no P0/P1 bugs open against the feature.

9. Open Risks

  • Wi-Fi 7 driver maturity (Epic 7): mainline OpenWrt/mac80211 support for the newest Wi-Fi 7 silicon is still maturing — do not commit a launch date until a dedicated hardware/driver spike confirms a viable, well-supported chipset.
  • Hardware tier decision (Epic 17): single router vs. mesh-first design is still an open question from Sadd's original brief — most homes over ~1,500 sq ft need mesh per the user-needs analysis; resolve before committing to Epic 17's SKU ladder.
  • Epic 16's two-path onboarding vs. Sadd's "never require a settings menu" principle: confirm the beginner/expert branch in US-16.2 is framed as pacing, not a gate, so it doesn't contradict Sadd's core simplicity promise.
  • Accessibility scope (Epic 16): the WCAG 2.1 AA audit is a meaningful scope addition — confirm design/QA capacity before committing it to Release 1.1.
